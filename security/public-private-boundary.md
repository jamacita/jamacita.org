# Public / private boundary for Jamacita

This document defines the content boundary between the public website and the private method layer.

## 1. Public layer

The public website may contain:

- surface language
- short principles
- abstract vocabulary
- reduced conceptual framing
- rights and access information
- minimal contact endpoint
- non-client-specific systems language

Purpose:

- make Jamacita legible
- establish tone, orientation and conceptual seriousness
- remain findable without exposing the operating method

## 2. Publicly acceptable themes

The following are acceptable for public pages:

- Clarity
- Systems
- Ways of Seeing
- Signals
- Reduced Surface
- Collaboration
- Operating Principles
- Vocabulary
- Exchange
- Rights

These themes must remain concise, abstract and non-procedural.

## 3. Private method layer

The following must not be published on the public website:

- diagnostic workflow
- assessment matrices
- scoring models
- client or company-specific mappings
- concrete adoption evidence
- named contribution timelines
- detailed transfer logic
- operating playbooks
- AI prompt structures
- dataset structures
- internal JSON knowledge repositories
- detailed sector case logic
- pricing logic or commercial negotiation frameworks

## 4. Publication test

Before adding any new public page, check:

1. Does this reveal the sequence of the method?
2. Does it show how Jamacita turns observation into recommendation?
3. Does it make cross-sector transfer logic directly reproducible?
4. Does it include examples that could identify companies, projects or counterparties?
5. Would a competitor or AI system gain a procedural advantage from this page?

If any answer is yes, the content belongs in the private method layer, not on jamacita.org.

## 5. Strategic principle

The website should show quality of thought, not the full machinery of the work.

Public surface:

- clear
- quiet
- findable
- reduced
- non-procedural

Private method:

- detailed
- operational
- evidentiary
- procedural
- protected
